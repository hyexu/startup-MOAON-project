## 한 일

### 1. AI 인터뷰 방식 설계
- 인터뷰 지침을 작성했습니다(`skills/life-story-interviewer/SKILL.md`).
  - 질문은 한 번에 하나만 합니다.
  - 답에 나온 구체적인 단어를 이어받아 다음 질문을 만듭니다.
  - 깔때기 6단계(열기 → 장면 → 감각 → 인물·대사 → 감정 → 의미)로 기억을 끌어냅니다.
  - 기억이 안 날 때는 단서와 선택지를 줍니다.
  - 민감한 이야기는 넘어갈 수 있게 합니다.
  - 원고에 없는 사실을 지어내지 않습니다.
- claude.ai 체험판(`spike/memoir-interviewer.html`)을 만들어 대화 품질을 먼저 확인했습니다.

### 2. 팀 시스템 분석과 방향 결정
- 팀원(박유나)의 상품 사이트와 관리자 웹 공개 코드를 분석했습니다.
  - 데이터 구조, 상태 이름, 동의 항목, 녹음 링크 방식을 파악했습니다.
- 팀원 저장소에 접근할 수 없어서, **팀 시스템과 나중에 합칠 수 있게 맞추되 독립적으로 작동하는 환경**을 따로 만들기로 결정했습니다.
  - 상태 이름(녹취 도착 / 정리 중 / 정리 완료 / 고객 확인 / 확정)과 동의 항목, 디자인 색은 팀원 시스템과 똑같이 맞췄습니다.

### 3. 설계와 범위 결정
- 설계 문서를 썼습니다(`docs/superpowers/specs/2026-11-25-voice-interview-service-design.md`).
  - 목표, 비목표, 실패 조건을 정했습니다.
  - 어르신 사용성 원칙: 한 화면에 행동 하나, 큰 글씨, 음성 안내, 전화 지원
  - 개인정보 원칙: 국외 이전 동의를 따로 받고, 실명은 AI에 보내지 않음
- 대화 방식을 비교해서 정했습니다.
  - 실시간 음성 통화 방식 대신 **차례대로 주고받는 방식**을 택했습니다.
  - 이유: 질문 품질을 직접 통제할 수 있고, 답마다 원본 녹음이 따로 남고, 비용이 가장 낮습니다.
- 12월 14일 발표에 맞춰 **1단계(작동하는 핵심)와 2단계(원고 편집, 삭제 등)로 범위를 나눴습니다.**
- 구현 계획서를 작업 12개로 나눠 썼습니다(`docs/superpowers/plans/2026-11-25-voice-interview-phase1.md`).

### 4. 비용 구조 설계 (경제성)
- AI 유료 API 대신 **고려대 BAZE 게이트웨이**를 찾아 도입했습니다.
  - 키 하나로 Claude, 음성 인식(Soniox), 음성 합성(Gemini)을 모두 씁니다.
  - 매달 무료 크레딧이 있고, 학습에 쓰지 않는다는 정책도 확인했습니다.
- 크레딧 안전장치를 넣었습니다.
  - 키를 여러 개 넣으면 차례로 씁니다(팀원 키 공유 가능).
  - 크레딧이 떨어지면 AI가 멈추고, 미리 정한 질문으로 녹음을 계속 받습니다.
  - 글로 옮기기는 크레딧이 생긴 뒤로 미룹니다.
- 모든 AI 호출의 사용량을 기록해서, 한 권당 원가를 숫자로 낼 수 있게 했습니다.
  - 실측: 질문 하나 + 정리 + 읽어 주기 + 글로 옮기기 시험 1회 ≈ 20크레딧(약 6원, 추정)
- 서버는 Vercel 무료, DB는 Supabase 무료 플랜으로 구성해서, 시범 단계의 고정비가 0원입니다.

### 5. 서비스 구현 (`web/`)
- **부모님 화면**
  - 링크 → 동의 2단계 → 마이크 허용 → 질문 듣기 → 말로 답하기 → 오늘은 여기까지
  - 카카오톡 안 브라우저 안내, 녹음을 휴대폰에 임시 저장해 끊겨도 다시 보냄
  - 아이폰 화면 꺼짐 대응, 두 번 누르기 방지, 체험 모드
- **한 턴 처리**
  - 녹음 저장 → 글로 옮기기 → 다음 질문(Claude Sonnet 5.5) → 질문 읽어 주기
  - 이야기 카드 정리(Claude Haiku 5.5)는 뒤에서 따로 돕니다.
- **운영자 화면**
  - 부모님 등록, 질문 묶음(기본 18개 + 가족 질문), 링크 발급·중지
  - 대화 기록(녹음 재생과 글), 이야기 카드, 크레딧 띠와 AI 멈춤
- **개인정보 안내 페이지**와 설정·배포 안내서
- **품질 관리**
  - 자동 테스트 83개 + 브라우저 테스트 4개
  - 독립 코드 검토에서 지적된 10건을 각각 재현 테스트로 확인하고 고쳤습니다.
  - 가장 중요했던 건: 다른 부모님의 녹음에 접근할 수 있던 경로 우회 차단

### 6. 배포와 실제 환경 검증
- Supabase(DB, 비공개 녹음 저장소, 운영자 로그인)와 Vercel을 설정하고 배포했습니다.
- 배포 후 문제를 직접 찾아 해결했습니다.
  - DB 비밀번호 인증 오류(28P01)
  - 빈 녹음 처리 오류
- 문제를 빨리 찾으려고 설정 점검 주소(`/api/health`)와 실패 사유 표시 기능을 추가했습니다.
- 실제 휴대폰으로 부모님 흐름을 확인했습니다.

## 팀과 연결되는 지점

- 팀원 관리자 웹과 **상태 이름, 동의 항목, 디자인 색을 같게 맞춰서** 나중에 합치기 쉽습니다.
- 팀원 BAZE 키를 `BAZE_API_KEYS`에 추가하면 무료 크레딧이 두 배가 됩니다.
- 주문, 결제, 고객 문의는 팀원 사이트가 맡고, 이 서비스는 "인터뷰가 실제로 돌아가는 부분"을 맡습니다.
