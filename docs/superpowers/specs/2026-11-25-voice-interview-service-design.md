# 모아온 음성 인터뷰 서비스 설계

작성일: 2026-11-25
상태: 승인 (2026-11-25) · 1단계 범위 확정 · AI 경로 BAZE 게이트웨이

## 1. 왜 만드는가

모아온은 AI가 부모님과 대화하며 유년·학창·청년 시절 이야기를 끌어내고, 그것을 기록·윤문해 회고록으로 엮는 서비스다. 고려대 창업 수업에서 **실제 구현 정도**와 **경제성**으로 평가받고, MVP로 **소액의 실제 거래**를 만드는 것이 목표다.

팀원(박유나)이 상품 소개·사전 예약 사이트와 관리자 웹을 따로 만들고 있지만, 그 저장소와 서버 코드에는 접근할 수 없다. 그래서 이 저장소에서는 **서비스의 핵심 동작이 실제로 돌아가는 환경**을 독립적으로 만든다. 부모님이 링크를 눌러 말로 답하면 녹음이 저장되고, AI가 답을 듣고 다음 질문을 이어 가는 환경이다.

성공 기준:
- 실제 부모님(가족 시범 대상) 한 분이 휴대폰 링크 하나로, 도움 없이 또는 전화 안내 정도만 받고 20분 이상 인터뷰를 이어 갈 수 있다.
- AI가 직전 답변의 구체적인 단어를 이어받아 질문한다 (PROGRESS.md 시범 평가 기준 ①).
- 원고 초안에 화자가 하지 않은 말이 들어가지 않는다 (평가 기준 ②). 들어가면 사람이 검토 단계에서 잡을 수 있다.
- 세션별·부모님별 실제 AI 비용이 기록되어, 한 권당 원가를 숫자로 제시할 수 있다 (경제성 평가 자료).

## 2. 목표 / 비목표 / 실패 조건

**목표 (이번 범위)**
1. 부모님 초대 링크와 동의: 운영자가 부모님을 등록하고 링크를 발급한다. 부모님은 링크를 처음 열 때 쉬운 말로 된 동의 화면을 본다.
2. 생애 질문 묶음: 시기별 질문 씨앗(SKILL.md 2-6)을 기본으로, 운영자가 부모님마다 넣고 빼거나 가족이 여쭙고 싶은 질문을 추가한다.
3. 링크 기반 음성 답변: 회원가입·앱 설치 없이 녹음한다. 답마다 원본 녹음이 저장된다.
4. AI가 질문을 이어 가는 대화: 답을 글로 옮기고, Claude가 SKILL.md 원칙에 따라 다음 질문을 만들고, 그 질문을 소리와 큰 글씨로 보여 준다.
5. 전사와 AI 초안: 녹음을 글로 옮긴 원문, 에피소드 카드, 시기별 원고 초안.
6. 사람의 편집·사실 확인: 운영자가 전사와 원고를 고치고, [확인 필요] 항목과 비공개 표시를 관리한다. 사람이 확정하기 전에는 원고가 "초안" 상태로 남는다.
7. 자료 열람·보관·삭제: 운영자가 녹음·글을 내려받고 삭제할 수 있다. 부모님 단위 전체 삭제, 보관 기한, 삭제 기록.
8. 비용 기록과 안전장치: 모든 AI 호출(글로 옮기기, 질문 생성, 기록 정리, 원고, 음성 합성)의 사용 크레딧과 원화 추정액을 남기고, 크레딧이 떨어지면 AI 질문을 멈추고 녹음만 받는다 (6-6).

**비목표 (이번 범위 밖, 나중 단계)**
- 주문·결제·사전 예약·고객 문의 (팀원 사이트가 맡음)
- 부모님 최종 승인 화면, PDF·실물 책 제작, 책 QR 음성 재생 페이지 (데이터 구조만 대비하고 화면은 다음 단계)
- 카카오톡·문자 자동 발송 (운영자가 링크를 직접 보낸다)
- 실시간 음성 대화, 생성형 음성 복제·이미지·영상, 여러 가족 구성원 권한 체계, 자동 출판

**실패 조건 (작동하더라도 실패로 본다)**
- 부모님이 한 화면에서 무엇을 눌러야 할지 헷갈리거나, 키보드 입력이 필요하다.
- AI가 질문을 여러 개 한꺼번에 던지거나, 캐묻거나, 기억을 정정한다.
- 원고에 지어낸 사실·대사가 들어가고, 그것이 검토 없이 "확정"된다.
- 삭제했다고 안내한 녹음이 어딘가에서 계속 재생되거나 남아 있다.
- 부모님 실명·연락처가 AI 제공사로 불필요하게 전달된다.
- 공개 저장소(GitHub)에 실제 인터뷰 내용이나 키가 올라간다.

## 3. 제약

- 사용자: 65세 이상. 2023년 노인실태조사(KISDI 인용)에서 67.2%가 정보화 적응에 어려움을 느낀다. 한 화면에 행동 하나, 큰 글씨(본문 20px 이상, 버튼 높이 64px 이상), 음성 안내, 모든 화면에 운영자 전화번호.
- 휴대폰: 안드로이드 크롬, 아이폰 사파리, **카카오톡 안에서 열린 브라우저**에서 녹음이 되어야 한다. 카카오톡 안 브라우저에서 마이크가 막히면 "다른 브라우저로 열기" 안내를 한다.
- 녹음 형식: 안드로이드는 webm/opus, 아이폰은 mp4/aac로 나온다. 둘 다 받아야 한다.
- 서버 응답 본문 4.5MB 제한(Vercel): 녹음 파일은 서버를 거치지 않고 저장소에 직접 올린다 (서명된 업로드 주소).
- 공개 저장소: 키·실제 데이터는 저장소에 넣지 않는다. 시험 데이터는 가명.
- 개인정보: 무엇이 AI 제공사로 가는지(모두 마인드로직 BAZE 게이트웨이(국내)를 거쳐 녹음 → Soniox, 질문 음성 → Google, 글 → Anthropic, 모두 국외), 보관 기간, 내려받기·삭제 방법을 동의 화면과 안내 페이지에 쉬운 말로 쓴다. AI 제공사로 보내는 글에는 부모님 실명·연락처를 넣지 않고 호칭(예: "어머님")만 쓴다.
- 팀원 시스템과 나중에 합칠 수 있도록 용어와 상태 이름을 맞춘다: 전사 상태 `녹취 도착 / 정리 중 / 정리 완료 / 고객 확인 / 확정`, 원고 상태 `초안 / 고객 확인 / 확정`, 동의 항목 `개인정보 수집·이용 / 음성 녹음과 보관 / AI 처리 위탁(국외 이전 포함) / 책 제작 업체에 원고 제공 / 오픈·진행 안내 수신`. 디자인은 팀원 사이트의 색(`#2E5A4C` 진녹색, 세이지 `#9FB283`, 배경 `#F5F5F7`)과 시스템 고딕 계열에 맞춘다.

## 4. 검토한 방식

| 방식 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **A. 차례대로 주고받기** (말하기 → 다 했어요 → 글로 옮기기 → Claude 다음 질문 → 읽어 주기) | SKILL.md를 Claude에 그대로 써서 질문 품질을 직접 통제. 답마다 원본 녹음이 따로 남음. 화면 꺼짐에 강함. 가장 저렴 | 질문이 나오기까지 몇 초 기다림 | **선택** |
| B. 실시간 음성 대화 (OpenAI Realtime, ElevenLabs) | 통화처럼 자연스러움 | 대화를 이끄는 AI가 Claude가 아님, 비용 몇 배, 아이폰 화면 꺼지면 끊김 | 제외 |
| C. claude.ai 체험판 계속 개선 | 이미 있음, 비용 없음 | 실제 고객이 쓸 수 없음 | 질문 품질 실험용으로만 유지 (`spike/`) |

AI 제공 경로: 처음에는 OpenAI·Anthropic API를 직접 쓰기로 했으나, 고려대가 제공하는 **BAZE API Gateway**(마인드로직)로 바꿨다. 키 하나로 Claude(질문·정리·원고), Soniox STT(글로 옮기기), Gemini TTS(읽어 주기)를 모두 쓸 수 있고, 매달 무료 크레딧(키당 5,000)이 있으며, 제공사 정책상 학습에 쓰이지 않는다. 비교했던 다른 음성 서비스(OpenAI, ElevenLabs, 네이버 클로바)로 바꿀 수 있도록 AI 호출은 한 곳에 모은다.

## 5. 결정된 구성 (사용자 승인)

- 대화 방식: A (차례대로 주고받기)
- AI 호출은 모두 BAZE API Gateway (`https://api.baze.co/v1/gateway`)
  - 질문 생성: Claude Sonnet 5.5 (Anthropic Messages 형식, `/claude/v1/messages`)
  - 기록 정리(이야기 카드): Claude Haiku 5.5 (비용 절감, 시범 결과를 보고 Sonnet으로 올릴 수 있게 설정값)
  - 원고 초안: Claude Opus 5.5 (2단계)
  - 글로 옮기기: `stt-async-v5` (비동기: 작업 시작 → 상태 확인, 결과는 1시간 뒤 삭제되므로 받는 즉시 저장)
  - 읽어 주기: `gemini-3.8-flash-tts` (말투 지시: "어르신께 여쭙듯 천천히, 따뜻하고 또렷하게")
  - 키는 여러 개(사용자 키 + 팀원 키)를 순서대로 쓴다 (6-6)
- 서버와 화면: Next.js (App Router), Vercel에 배포
- 데이터: Supabase (Postgres + 비공개 저장소 + 운영자 로그인)

## 6. 동작 설계

### 6-1. 부모님 화면 (휴대폰, 링크 `/r#k=토큰`)

토큰은 URL의 `#` 뒤에 둬서 서버 로그와 다른 사이트로 새지 않게 한다. 서버에는 토큰의 해시만 저장한다. 링크는 기본 90일 유효, 운영자가 중지할 수 있다.

한 화면에 행동 하나:
1. **인사** — "○○님, 안녕하세요. 모아온입니다." 무엇을 하는 곳인지 두 문장. [시작하기]. 아래에 운영자 전화번호.
2. **동의** (처음 한 번, 두 화면) — 개인정보보호법상 국외 이전은 따로 동의받아야 하므로 화면을 둘로 나눈다. 각 화면은 안내 몇 줄 + [동의합니다] 버튼 하나 + [읽어 주세요](소리로 안내) + "동의하지 않으셔도 됩니다. 그러면 녹음은 하지 않고, 전화로 여쭤보는 방법을 안내해 드려요."
   - 화면 ①: 녹음과 보관 — 무엇을 모으는지(목소리 녹음, 답하신 내용), 왜(책을 만들기 위해), 누가 보는지(가족과 모아온 담당자), 얼마나 보관하는지(보관 기한), 언제든 내려받기·삭제 요청 가능, AI 학습에 쓰지 않음. 동의 항목: `개인정보 수집·이용`, `음성 녹음과 보관`.
   - 화면 ②: AI 처리와 국외 이전 — 녹음과 글은 국내 업체 마인드로직(BAZE)을 거쳐, 글로 옮기기 위해 Soniox(미국)로, 질문을 소리로 만들기 위해 Google(미국)로, 질문과 원고를 만들기 위해 Anthropic(미국)으로 보내며, AI 학습에는 쓰이지 않고 성함·연락처는 보내지 않음. 동의 항목: `AI 처리 위탁(국외 이전 포함)`.
   - `책 제작 업체에 원고 제공`, `오픈·진행 안내 수신`은 이 화면에서 받지 않는다 (책 제작 단계와 신청 자녀 쪽에서 받을 항목).
   - 항목·문구 버전·시각을 서버에 기록. 두 동의가 모두 있어야 녹음 화면으로 간다.
   - 화면 아래에 쉬운 말로 쓴 개인정보 안내 페이지(`/privacy`) 링크.
3. **마이크 허용 안내** — 그림 한 장과 "다음 화면에서 '허용'을 눌러 주세요". 카카오톡 안 브라우저에서 막히면 "오른쪽 위 ⋮ → 다른 브라우저로 열기" 그림 안내.
4. **질문 화면** (반복) — 질문 한 문장을 아주 크게, 자동으로 읽어 준다(소리 켜짐이 기본, 끄기 가능). 버튼 하나 [● 말하기].
5. **녹음 중** — 경과 시간, 소리 크기 막대, 버튼 하나 [■ 다 했어요]. 5분이 되면 자동으로 끝내고 넘긴다. 작은 글씨로 "질문 다시 듣기".
6. **듣는 중** — "잘 들었어요. 잠시만요…" (미리 만들어 둔 음성으로 즉시 재생). 그동안 업로드 → 글로 옮기기 → 다음 질문.
7. 다음 질문이 오면 4로. 화면 아래에 작은 [오늘은 여기까지] 버튼 → AI가 오늘 이야기를 2~3문장으로 되짚고 다음에 이어 갈 주제를 말해 준다 → 끝 화면.

추가 동작:
- **"기억이 안 나요" / "이건 넘어갈게요"**: 질문 화면에 작은 글씨 버튼 두 개. 누르면 그 뜻을 대화에 넣고 AI가 다른 질문을 한다 (SKILL.md 2-3, 3).
- **다시 들어올 때**: 지난 세션이 있으면 AI가 지난 이야기를 한 문장으로 떠올리며 인사하고 이어 간다.
- **녹음 보호**: 녹음 중에는 몇 초마다 휴대폰 안(IndexedDB)에 저장해, 창이 닫히거나 업로드가 실패해도 다시 열면 이어서 보낸다. 업로드는 몇 번 재시도한다.
- **화면 꺼짐**: 녹음 중 화면 켜짐 유지(Wake Lock). 아이폰에서 화면이 꺼져 녹음이 멈추면, 그때까지 녹음은 보내고 "다시 말하기"로 이어 간다.
- **소리가 거의 없을 때**: 글로 옮긴 결과가 비어 있으면 "소리가 잘 안 들렸어요. 한 번만 더 말씀해 주시겠어요?"로 같은 질문을 다시 한다.

### 6-2. 한 턴의 서버 처리

```
[다 했어요]
  → 휴대폰이 서버에 업로드 주소 요청 (토큰 확인)
  → 녹음을 Supabase 비공개 저장소에 직접 업로드
  → 서버에 "업로드 끝" 알림
       1. 글로 옮기기 (stt-async-v5, language_hints=ko, 화자 분리 끔). 비동기라 1~2초 간격으로 상태 확인.
          BAZE STT는 webm을 받지 않으므로(길이 정보 없음), 안드로이드 크롬의 webm/opus 녹음은 서버에서 ogg/opus로 다시 담거나(재인코딩 없이) 다른 받는 형식으로 바꿔 보낸다. 아이폰 mp4는 그대로.
       2. 질문 생성 (Claude, 스트리밍 아님. 아래 6-3)
       3. 질문 음성 만들기 (gemini-3.8-flash-tts → 24kHz PCM을 mp3 또는 wav로 바꿔 저장)
       4. 질문 글 + 음성 주소를 휴대폰에 돌려줌
  → (뒤에서) 기록 정리 (Claude, 에피소드 카드 갱신)
```

- 목표 지연: [다 했어요]부터 다음 질문 소리가 나기까지 보통 10초 이내. 기다리는 동안 "잘 들었어요"가 바로 나온다.
- 질문 생성이 실패하면 질문 묶음의 다음 씨앗 질문으로 대신한다 (대화가 멈추지 않게). 실패는 기록한다.
- 기록 정리는 대화를 막지 않는다. 다음 질문 생성은 직전까지 정리된 카드를 쓴다.

### 6-3. AI 역할과 지시문

`skills/life-story-interviewer/SKILL.md`를 원본으로 삼아 세 개의 지시문으로 나눈다. 코드 안 `prompts/` 폴더에 두고 버전을 남긴다. 저장되는 모든 AI 결과에는 어느 지시문 버전으로 만들었는지 기록한다.

1. **인터뷰어** — 입력: 지시문 + 현재 기록 상태(시기별 채움 정도, 에피소드 목록과 깔때기 단계, 지금 다루는 에피소드) + 질문 묶음(남은 씨앗) + 지난 세션 요약 + 최근 대화(최근 약 30턴). 출력: 화자에게 할 말 한 턴(공감 1문장 + 질문 1개, 2~3문장, 소리로 읽기 좋게 마크다운·괄호 없이). 음성으로 읽힐 것을 전제로 짧게.
2. **기록자** — 입력: 현재 기록 상태 JSON + 최근 대화. 출력: 갱신된 기록 상태 JSON (체험판 `spike/memoir-interviewer.html`의 RECORDER_RULES 형식: 화자 정보, 지금 시기, 시기별 채움 0~3, 에피소드 카드 배열). 원래 표현 인용은 전사 원문에서 그대로.
3. **편집자** — 운영자가 시기(장)를 골라 요청할 때만. 입력: 그 시기의 에피소드 카드 + 해당 전사 원문. 출력: 1인칭 회고체 원고, [확인 필요: …], [사진: …] 표시. 지어내지 않기 원칙.

모델 선택은 구현 시점의 최신 모델 중에서 고른다: 인터뷰어는 지연이 중요하므로 빠른 쪽, 편집자는 품질이 중요하므로 가장 좋은 쪽. 모델 이름은 설정값으로 둔다.

AI 제공사로 보내는 글에는 부모님 성함·연락처를 넣지 않는다. 화자는 운영자가 정한 호칭으로만 부른다.

### 6-4. 운영자 화면 (`/admin`, 이메일 로그인)

운영자는 1~3명, 모두 같은 권한 (권한 구분은 비목표).
- **부모님 목록**: 호칭, 진행 상태, 마지막 답변 시각, 시기별 진행 점(●●○), 이번 달 비용.
- **부모님 등록·수정**: 호칭(AI가 부를 이름), 실명(운영용, AI로 보내지 않음), 출생 연도, 고향, 직업, 가족 메모(STT 힌트와 질문 맥락), 보관 기한(기본 1년), 신청한 자녀 연락처(운영용).
- **질문 묶음**: 시기별 기본 씨앗 목록에서 켜고 끄기, 가족 질문 추가, 순서 바꾸기. 기본 씨앗은 코드에 둔다.
- **링크**: 발급(링크를 한 번만 보여 주고 복사 버튼), 중지, 마지막 사용 시각. 카카오톡으로 보낼 문안 예시 함께 복사.
- **대화 기록**: 세션별로 질문 → 녹음 재생 → 전사 원문. 전사는 고칠 수 있고, 고친 사람과 시각이 남는다 (AI 원본도 보존). 상태: 녹취 도착 / 정리 중 / 정리 완료 / 고객 확인 / 확정.
- **이야기 카드**: 기록자가 만든 카드 목록. 고치기, 비공개·확인 필요 표시, 카드 합치기는 비목표(고치기로 대신).
- **고객 확인**: 이번 범위에서는 시스템 밖에서 한다. 운영자가 원고를 내려받아 가족에게 보내고, 의견을 받아 직접 고친 뒤 상태를 손으로 바꾼다. 가족·부모님 열람 화면은 다음 단계.
- **원고**: 시기별 [초안 만들기] → 편집 가능 본문. [확인 필요] 목록과 비공개 목록을 따로 보여 준다. 상태: 초안 / 고객 확인 / 확정. "확정"은 운영자가 [확인 필요]를 모두 해결해야 누를 수 있다.
- **내려받기·삭제**: 부모님 단위로 녹음(zip) + 전사·카드·원고(텍스트) 내려받기. 녹음 하나 삭제, 부모님 전체 삭제(실제 저장소 파일까지 삭제, 삭제 기록은 남기되 내용은 남기지 않음). 보관 기한이 지나면 운영자 화면에 경고 (자동 삭제는 비목표; 운영자가 버튼으로 실행).
- **비용**: AI 호출별 사용량(토큰, 초) → 추정 금액(원화 환산), 부모님별·세션별·월별 합계, 한 턴 평균 비용. 단가는 설정값.

### 6-5. 데이터 (Supabase)

- `parents` 부모님 (호칭, 실명, 출생, 고향, 직업, 가족 메모, 자녀 연락처, 보관 기한, 상태)
- `links` 녹음 링크 (부모님, 토큰 해시, 만료, 중지 시각, 마지막 사용)
- `consents` 동의 기록 (부모님, 항목, 문구 버전, 시각, 경로=링크)
- `question_seeds` 부모님별 질문 묶음 (시기, 질문, 출처=기본/가족, 순서, 사용 여부)
- `sessions` 세션 (부모님, 시작·끝, 끝낸 방법, 요약)
- `turns` 턴 (세션, 순서, AI 질문 글, 질문 음성 경로, 녹음 경로, 녹음 길이, 전사 원문, 사람이 고친 전사, 상태, 버튼 명령 여부)
- `memory` 부모님별 기록 상태 JSON (기록자 결과, 버전 이력은 `memory_versions`)
- `chapters` 시기별 원고 (본문, 상태, 지시문 버전, 고친 사람)
- `ai_usage` AI 호출 기록 (종류, 모델, 입력·출력 토큰 또는 초, 추정 비용, 부모님, 세션)
- `deletions` 삭제 기록 (무엇을, 누가, 언제 — 내용 없이)

저장소: `audio` 버킷(비공개). 재생은 짧게 유효한 서명 주소로만. 질문 음성도 같은 버킷.

권한: 모든 표는 RLS로 막고 운영자만 읽는다. 부모님 화면은 토큰을 서버에서 확인한 뒤 서버가 서비스 키로 처리한다 (부모님 휴대폰에는 다른 부모님 데이터에 닿는 키가 없다).

### 6-6. 크레딧 안전장치

- **키 여러 개**: 서버 설정값 `BAZE_API_KEYS`에 키를 쉼표로 여러 개 넣는다 (사용자 키, 팀원 키). 앞의 키부터 쓰고, 잔액 부족(402)이나 남은 크레딧이 기준 아래면 다음 키로 넘어간다. 각 키의 남은 크레딧은 BAZE 잔액 조회(`/credits/`)로 몇 분마다 확인해 저장한다. 어떤 키로 호출했는지는 키 이름(예: `key1`)만 기록하고 키 값은 기록하지 않는다.
- **멈춤 기준**: 모든 키의 남은 크레딧 합이 설정값(기본 300크레딧, 약 3턴분) 아래로 떨어지면 **AI 멈춤 모드**로 바꾼다.
- **AI 멈춤 모드에서 부모님 화면**: 화면은 그대로 이어진다. 다음 질문은 질문 묶음의 다음 씨앗 질문(미리 만들어 둔 글)으로 나오고, 읽어 주기는 미리 만들어 둔 음성이 있으면 그것을, 없으면 휴대폰 내장 음성으로 읽는다. 녹음은 계속 저장되고, 글로 옮기기는 미뤄 두었다가 크레딧이 다시 생기면(매월 1일 갱신) 운영자가 [미뤄 둔 녹음 글로 옮기기]로 처리한다.
- **운영자 화면**: 키별 남은 크레딧, 이번 달 사용량, AI 멈춤 여부를 맨 위에 보여 준다. 운영자가 직접 AI를 멈추거나 다시 켤 수 있다.
- **추가 한도**: 부모님별 하루 최대 80턴 (설정값). 넘으면 같은 방식으로 씨앗 질문만 쓴다.
- **씨앗 질문 음성 미리 만들기**: 운영자가 질문 묶음을 저장할 때, 크레딧이 충분하면 씨앗 질문 음성을 미리 만들어 저장해 둔다 (AI 멈춤 모드와 응답 속도 모두에 도움).

### 6-7. 시연 모드

`/r?demo=1`: 서버와 AI 없이 미리 정해 둔 가상 대화로 부모님 화면 전체를 체험한다 (수업 발표, 녹음 권한 확인용). 녹음은 휴대폰 안에서만 재생하고 아무것도 보내지 않는다.

## 7. 단계와 일정

수업 발표: **2026-12-14**. 그 전에 가족 시범을 최소 1회 한다.

**1단계 (발표 전, 이번 계획 범위)**
- 부모님 화면 전체: 인사 → 동의 두 화면 → 마이크 안내 → 질문·녹음 반복 → 오늘은 여기까지. 녹음 보호(휴대폰 임시 저장·재전송), 화면 켜짐 유지.
- 한 턴의 서버 처리: 업로드 → 글로 옮기기 → 질문 생성 → 질문 음성. 기록자(에피소드 카드 갱신)는 뒤에서 실행.
- AI 비용 기록(`ai_usage`)과 운영자 화면의 간단한 비용 합계 (경제성 발표 자료).
- 최소 운영자 화면: 로그인, 부모님 등록·수정, 질문 묶음(기본 씨앗 켜고 끄기, 가족 질문 추가), 링크 발급·중지, 대화 기록 보기(질문·녹음 재생·전사), 이야기 카드 읽기.
- 시연 모드(`/r?demo=1`) — 발표장에서 인터넷·권한 문제가 있어도 흐름을 보여 줄 수 있게.
- 개인정보 안내 페이지(`/privacy`).

**2단계 (발표 후)**
- 전사·카드 편집과 수정 이력, 원고 초안과 편집, [확인 필요] 관리, 상태 확정.
- 내려받기(zip)·부모님 전체 삭제·삭제 기록, 보관 기한 경고.
- 비용 화면 확장(세션별, 한 턴 평균, 원화 환산 설정).
- 부모님 최종 승인, PDF, QR 재생 (3단계 이후일 수 있음).

데이터 구조(6-5)는 1단계부터 2단계 표까지 만들어 두되, 화면은 단계에 맞춰 만든다.

## 8. 계정과 비용

- 시범·발표 단계는 **무료 플랜**: Vercel Hobby, Supabase Free. 실제 결제를 받기 시작하면 Vercel Pro, Supabase Pro로 올린다 (Vercel 무료 플랜은 상업적 사용 금지, Supabase 무료는 저장 1GB·7일 미사용 시 일시 정지).
- 1단계 제약: Supabase 무료 저장 1GB → 녹음은 64kbps 안팎으로 저장(5분 답변 ≈ 2.4MB, 1GB ≈ 400개 답변). 시범 규모(부모님 몇 분)에 충분. 무료 플랜 서버 함수 실행 시간 안에 한 턴 처리가 끝나야 하므로, 기록자 같은 뒤 작업은 따로 요청을 나눠 실행한다.
- 계정: AI는 고려대 BAZE 키(사용자 + 팀원 각 1개, 키당 월 5,000 무료 크레딧, 매월 1일 갱신). Vercel, Supabase는 새로 만든다 (사용자가 가입, 키는 안전한 입력 창이나 Vercel 환경 변수로만 넣는다).
- 무료 크레딧 규모: 시험 호출 1건 기준 1크레딧 ≈ 0.3원 추정, 키당 월 약 1,300원어치. 질문 Sonnet + 정리 Haiku + 캐시 기준 한 턴 약 60~100크레딧 → 키 두 개로 월 약 100~160턴. 개발·발표 시연에는 충분하고, 가족 시범을 넉넉히 하려면 나중에 BAZE 크레딧 충전(지금은 하지 않음).
- 실제 차감 크레딧은 BAZE 응답의 사용량으로 `ai_usage`에 쌓여 발표의 원가 근거가 된다.
- 안전장치는 6-6.
